# 研究任务管理

思路借鉴自 Matt Pocock 公开的 skills 仓库(问题 → 任务 → 证据 → 决策的闭环),文字为原创,交付物换成了研究证据链。

## 层级

| 层级 | 在 GitHub(可选) | 在仓库里 | 用途 |
|---|---|---|---|
| 研究主线 | 一个主 Issue | `PROJECT.md` + 相关想法笔记 | 问题边界、未决问题、阶段性决定 |
| 可验证任务 | 主线下的子 Issue | 明确的笔记、实验目录或写作文件 | 一次只回答一个问题 |
| 证据 | Issue 评论里的路径链接 | PDF、笔记、代码、日志、结果、图 | 让结论可复核 |
| 决策 | 主线里的"已决定" | `research-log.md`;重大的写 ADR | 防止后续会话推翻既定前提 |

不用 GitHub 也可以,只靠仓库里的文件就够了。

## 任务状态

- `needs-triage`:问题存在,还没判断价值和优先级。
- `needs-info`:缺论文、数据、导师意见或实验条件,暂时不能可靠执行。
- `ready-for-agent`:输入、产出路径、完成标准都明确,AI 可独立执行。
- `ready-for-human`:必须由你、导师或其他人完成,例如导师确认、账号授权、主观取舍。
- `wontfix`:明确不做,并记录原因。

## 从想法到结论

1. **捕获**:模糊想法先写进 `research-notes/brainstorming/`,不要立刻包装成"创新点"。
2. **核验**:查已有工作,写清最接近的论文、差异、威胁和可证伪条件。
3. **立项**:问题值得连续推进时才建主线;一次性任务不需要。
4. **拆任务**:每个任务写明问题、输入、输出路径、完成标准、阻塞项。
5. **执行**:实验必须可复现,调研必须可追溯来源。
6. **收证**:结果存进固定目录;在评论里只写摘要和路径。
7. **决策**:回答"继续、修改还是放弃",更新 `research-log.md`;长期结构性决定写 ADR。
