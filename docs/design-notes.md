# 设计思路

## 要解决的问题

做研究的人通常有三堆东西:**文献**(PDF 和元数据)、**读过之后的理解**(笔记、脉络)、**正在推进的研究**(实验、写作、日志)。AI 能帮上忙,但它每次对话都从零开始,不知道你的规矩,容易乱放文件、另起炉灶、改动你不想碰的原始材料。

## 设计原则

1. **各管一层**:Zotero 管原件,Obsidian 管沉淀,研究项目管推进。AI 不替代任何一层。
2. **总纲 + 分层规则**:`SYSTEM.md` 说明关系和通用原则,每一层有自己的规则文件,以它为准。
3. **唯一路由表**:任何产出都能通过"它是什么"确定路径,不按日期、工具或会话建目录。
4. **在框架内改**:不新建平行体系;要改规则,先征得你同意,再改规则文件本身。
5. **原始材料只读**:`raw/` 对 AI 只读,出错时永远能回到原文。
6. **不编造**:缺信息就写 `待确认`。
7. **手动触发**:整理和维护默认只在你开口时执行,不偷偷在后台改你的文件。

## 目录与权限

| 目录 | AI 的权限 | 用途 |
|---|---|---|
| `knowledge-base/raw/` | 只读(`raw/web/` 仅可新增) | 原始材料 |
| `knowledge-base/wiki/` | 读写 | AI 整理后的主题页,页面间用 `[[双向链接]]` |
| `knowledge-base/outputs/` | 只写 | 报告、问答结果等衍生产出 |
| `knowledge-base/journal/` | 读写 | 每日进度 |
| `research-project/` | 按路由表 | 论文、笔记、实验、写作,临时产物进 `.local/`(不进 git) |

## 取舍

| 问题 | 选择 | 理由 |
|---|---|---|
| 自动整理还是手动 | 手动触发 | 先让规则稳定,再考虑自动化;自动化容易在你没注意时改坏东西 |
| 一个大知识库还是多个 | 一个 vault + 一个项目 | 多套体系会让 AI 和人都找不到东西 |
| 规则写在对话里还是文件里 | 文件里 | 新对话也能读到,而且有版本记录 |
| Zotero 和 Obsidian 的衔接 | 不预设 | 每个人的习惯不同,强行规定容易不适用 |

## 思路来源

项目管理部分(问题 → 任务 → 证据 → 决策的闭环、用标签区分"AI 可独立做"和"必须人来做")借鉴了 Matt Pocock 公开的 skills 仓库里的思路。本仓库的文字均为原创。

## 刻意不包含的东西

任何真实的研究内容、论文、笔记、Zotero 数据、个人材料。仓库里的示例都是占位。
